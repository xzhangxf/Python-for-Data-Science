# Python - 4 - Dod

This module focuses on Data Oriented Design (DOD) through utility-style functions, closures, decorators, and dataclasses.

## Module Overview

What this module teaches:

- Statistical computation from variadic arguments
- Closure behavior and persistent internal state
- Decorator-based function call limits
- Dataclass modeling with generated fields

How it connects to the repository:

- Complements OOP with function-first design patterns
- Emphasizes practical, reusable units over large class hierarchies

Prerequisites:

- Python functions and control flow
- Basic understanding of classes/dataclasses

## Learning Goals

- Compute mean/median/quartile/std/variance from flexible inputs
- Build closure counters (`outer` -> `inner`)
- Write decorators that enforce call constraints
- Create dataclasses with `init=False` fields and post-init logic

## Exercise-by-Exercise Explanation

### ex00 - statistics.py

**Path:** `Training Piscine Python for datascience - 4/ex00/statistics.py`
**Purpose:** Print selected statistics from variable-length inputs.
**Important Function:** `ft_statistics(*args, **kwargs)`.
**Input:** Numeric positional args and keyword requests like `mean`, `median`, `quartile`, `std`, `var`.
**Output:** Requested metrics or `ERROR`.
**Main Logic:** Build local stat functions -> map labels to functions -> evaluate by kwargs values.
**How to Run:**
```bash
python3 "Python - 4 - Dod/Training Piscine Python for datascience - 4/ex00/tester.py"
```
**Example Output:** Includes `mean : 95.6`, `median : 42`, etc.
**What I Learned:** Dynamic dispatch with function dictionaries.

### ex01 - in_out.py

**Path:** `.../ex01/in_out.py`
**Purpose:** Demonstrate closures with stateful inner function.
**Important Functions:** `square`, `pow`, `outer`.
**Input:** Initial number and transform function.
**Output:** New transformed value each call.
**Main Logic:** `outer` captures `x` and updates it on each `inner()` call.
**How to Run:**
```bash
cd "Python - 4 - Dod/Training Piscine Python for datascience - 4/ex01"
python3 tester.py
```
**What I Learned:** Nonlocal state and function factories.

### ex02 - callLimit.py

**Path:** `.../ex02/callLimit.py`
**Purpose:** Decorator that limits number of function calls.
**Important Function:** `callLimit(limit)` returning nested decorators.
**Input:** Limit integer and decorated function calls.
**Output:** Function executes until limit, then prints error.
**How to Run:**
```bash
cd "Python - 4 - Dod/Training Piscine Python for datascience - 4/ex02"
python3 tester.py
```
**What I Learned:** Decorator closure counters and wrapped call control.

### ex03 - new_student.py

**Path:** `.../ex03/new_student.py`
**Purpose:** Dataclass model with computed login and random ID.
**Important Components:** `generate_id()`, `Student` dataclass with `field(init=False)` and `__post_init__`.
**Input:** `name`, `surname`, optional `active`; `id`/`login` not init parameters.
**Output:** Student object repr generated by dataclass.
**How to Run:**
```bash
cd "Python - 4 - Dod/Training Piscine Python for datascience - 4/ex03"
python3 tester.py
```
**Example Behavior:** First instantiation prints student object; second with `id="toto"` raises `TypeError` (expected by subject).
**What I Learned:** Dataclass field control and post-init validation.

## Important Concepts

- Variadic function signatures (`*args`, `**kwargs`)
- Closures and `nonlocal`
- Decorators with nested wrappers
- Dataclass field options (`default_factory`, `init=False`)
- Runtime validation in `__post_init__`

## Data / Control Flow

```text
Input values / function references
        ↓
Validate / parse request
        ↓
Apply computation or decorator logic
        ↓
Return or print result
```

## Common Errors / Edge Cases

| Case | Where It Is Handled | Behavior |
|---|---|---|
| No positional numbers for stats | `ex00/statistics.py` | Prints `ERROR` |
| Unknown stat keyword value | `ex00/statistics.py` | Prints `ERROR` |
| Function called too many times | `ex02/callLimit.py` | Prints `Error: <function ...> call too many times` |
| Invalid student init with `id=` | `ex03/new_student.py` dataclass init | Raises `TypeError` |
| Empty/non-string names | `ex03/new_student.py` | Raises validation error in `__post_init__` |

## Key Takeaways

- Data-oriented utilities can be concise and powerful.
- Closures/decorators help control behavior without large classes.
- Dataclasses simplify structured data modeling.
- Input constraints are part of robust design, not optional extras.
